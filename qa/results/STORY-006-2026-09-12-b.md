# STORY-006 — Manual QA run — 2026-09-12 (TASK-014, re-execution)

**Task**: TASK-014 (Re-execute test cases, post dev-stack rebuild)
**Environment**: dev stack — `http://localhost:3100` (web), `http://localhost:8100` (backend)
**Result**: 6/7 test cases pass; 1 blocked by tooling; BUG-001 partially resolved (kept open — see below)

## Summary

Re-ran TC-192 through TC-198 after the user rebuilt the dev web stack (`./deploy.sh rebuild`).

First navigation to `http://localhost:3100/` still rendered the pre-STORY-006 DOM (no separators) —
investigation traced this to a **browser HTTP cache artifact**, not a still-stale server: `nginx.conf`'s
`location /` sets no `Cache-Control` header on `index.html`, so a browser that had visited the app
before the rebuild (this agent's own Playwright profile, from TASK-013) kept serving the old cached
page/bundle without a network round trip. A cache-busted navigation (`?_qa=...`) and a
`fetch(..., {cache:'no-store'})` both confirmed the server genuinely serves the current, rebuilt
frontend (image `Created` timestamp 2026-09-12; bundle contains STORY-006's code; DOM matches current
source once loaded fresh). Full detail and root-cause evidence added to **BUG-001**.

All further TCs were executed against cache-busted navigations to guarantee the current build.

Drag interactions were simulated via synthetic `PointerEvent` dispatch (`pointerdown`/`pointermove`/
`pointerup`) on the separator elements rather than a literal mouse drag — the Playwright MCP tool set
available in this session has no drag/mouse-gesture primitive. This exercises the same
`onPointerDown`/`onPointerMove`/`onPointerUp` handlers a real drag would (confirmed via
`ResizeHandle.tsx`), so it's a valid functional check, just noted here for transparency.

## BUG-001 — Verified status

- **Fixed and verified**: the original "no resize separator anywhere, stale image" symptom. Image
  rebuilt 2026-09-12, matches STORY-006 commits; DOM confirmed correct on a fresh load.
- **Still open**: container reports Docker `unhealthy` — root cause now identified as the healthcheck
  command using `http://localhost:3000` where `localhost` resolves to IPv6 inside the container, while
  nginx listens IPv4-only. Not a STORY-006 regression, but was bundled into this bug originally and still
  reproduces, so it stays open until devops fixes the healthcheck/nginx config.
- **New finding folded into the same bug**: `index.html` has no cache header, so browsers can silently
  keep serving a pre-rebuild build until a hard refresh — flagged as a devops/nginx config item, same
  bug (see BUG-001 update for full detail).
