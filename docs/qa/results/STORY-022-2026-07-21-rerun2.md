## New failure found — tc-009 regressed by TASK-004/006/007

**BUG-006** (new, `open`, `major`, assignee `frontend-developer`): the standalone Project Settings screen (`/projects/:id/settings`, TASK-004) intentionally renders no per-project sub-navigation tab bar (confirmed by its own test suite: "does not render a per-project sub-nav tab bar"). Combined with the Projects Management page's project-name link now pointing only to Settings (TASK-003) and no other in-app link to that project's Stories/Board/Milestones, a project not yet opened in Task Manager mode this session has **no clickable path** from its Settings screen (or from "Back to Projects") to its own Stories/Board/Milestones — contradicting the story's explicit AC: "Once inside a project via this entry point, the Stories, Board, and Milestones views remain fully reachable through the existing project sub-navigation tabs."

This differs from the prior run's tc-009 result (PASS, "Stories/Board/Milestones sub-nav tabs all loaded normally afterward") because at that time TASK-004 (standalone screen) had not yet shipped — Settings was still a tab inside `ProjectShell`, which did carry the sub-nav. TASK-004/006/007 changed that. A workaround exists (switch to Task Manager mode, then re-select the project from the sidebar), but it does not use "the existing project sub-navigation tabs" from this entry point as the AC describes. See `docs/stories/STORY-022-global-project-navigation/bugs/BUG-006-no-path-from-settings-to-stories-for-unvisited-project.md` for full repro steps.
