## Bugs re-verified this pass (all `fixed` → `resolved`)
- **BUG-002** (Session Detail long unbroken *context* overflow) — no longer reproducible for
  `context`/Goal/Result fields via `ReadField`. **Resolved.**
- **BUG-003** (no inline validation on Create/Edit Session forms) — inline alerts now appear for
  topic/goal on both forms; verified via TC-006 and TC-011. **Resolved.**
- **BUG-004** (Sessions list long unbroken topic breaks whole table) — table now uses
  `table-fixed`, offending row wraps in place, every other row's columns stay aligned. **Resolved.**
- **BUG-005** (select chevron spacing inconsistent) — every Sessions `<select>` (status,
  participant role ×2, linked story ×3, linked task ×2, app-mode switcher) now renders via the
  shared `SelectField` (`appearance-none` + `pr-8`), matching Task Manager. **Resolved.**

## New bug filed
- **BUG-006** (minor, frontend-developer) — Session Detail view: a long unbroken **topic** value
  still causes full-page horizontal overflow, because `topic` is rendered as the page's `<h1>`
  heading (not through the `ReadField` component BUG-002's fix targeted) and has no
  `overflow-wrap`/`word-break` treatment. Confirmed via `document.documentElement.scrollWidth`
  (7969px) vs. `clientWidth` (1512px), and via the `<h1>` element's own computed style
  (`overflow-wrap: normal`, `word-break: normal`). This is effectively the same defect class as
  BUG-002, on the one field BUG-002's fix didn't reach — its own repro used a long `context`, not
  a long `topic`. Causes tc-009 and tc-017 to fail.
