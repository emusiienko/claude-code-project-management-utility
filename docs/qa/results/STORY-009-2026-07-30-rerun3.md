## BUG-006 re-verification — still reproducible, reopened
Confirmed via DOM inspection that the `break-words` class **is** present on the `<h1>` and its
computed style does show `overflow-wrap: break-word` — the fix was applied, but it does not take
effect. Root cause: the `<h1>` is a direct flex item (parent `div.flex.flex-wrap.items-center`)
and flex items have an automatic minimum width (`min-width: auto` by default) that prevents them
from shrinking below their own intrinsic content width — regardless of `break-words` — unless the
item itself also has `min-width: 0` (or equivalent). Measured: `h1.getBoundingClientRect().width`
= 7705px (unwrapped, wider than its 1224px-wide flex container), `document.documentElement.scrollWidth`
= 7969px vs. `clientWidth` = 1512px — an unchanged, real page-wide horizontal overflow, visually
confirmed in `tc009-bug006-recheck-still-overflow.png`. Full root-cause detail and a note for the
next fix attempt (the `<h1>` itself needs `min-w-0` alongside `break-words`) added to
`docs/stories/STORY-009-session-tracking/bugs/BUG-006-session-detail-topic-heading-overflow.md`.
Status reverted `fixed` → `open` in the bug file and `bugs/index.md`.
